## Overview

RAG-06 establishes three critical operational frameworks:

1. **Golden-Set Evaluation Gate** — nightly CI job compares against committed baseline
2. **Observability & Alerting** — Grafana dashboards for retrieval metrics and refusal rates
3. **Operations** — backup/restore, right-to-be-forgotten deletion, weekly compaction

## 1. Golden-Set Evaluation Gate

### Versioning

The golden set is a versioned dataset of questions, expected answers, and source chunks:
- **Location:** `evals/datasets/rag_qa.jsonl` (primary), `evals/datasets/extraction.jsonl`, `evals/datasets/refusal.jsonl`
- **Version tracking:** Every eval run records `git_sha`, `timestamp`, and `golden_set_version` (SHA-256 hash of all dataset files, first 12 hex chars) in metadata

### Structure

```jsonl
{
  "id": "rag-001",
  "input": "What was the total revenue in Q3 2024?",
  "expected": "USD 52.4 million",
  "category": "factual_extraction",
  "context": "Q3 2024 Financial Report",
  "relevant_chunks": ["fin-q3-exec-summary", "fin-q3-kpi"]
}
```

### Baseline & Regression Detection

**Baseline:** `evals/results/baseline.json`
- Committed version: pass rate, confidence intervals (Wilson CI), per-example results
- Generated by: `python -m evals.runner --all --tag baseline`
- Format: JSON with metadata, per-dataset metrics, and per-example verdicts

**CI Job (`.github/workflows/ci.yml`):**
```yaml
on:
  push:            # runs on every push to main/tier-1/rag-prod
  pull_request:    # runs on PRs to those branches
  schedule:
    - cron: "0 2 * * *"   # nightly at 02:00 UTC

eval:
  - Run: python -m evals.runner --all --tag <SHA>
  - Compare: python -m evals.compare baseline <SHA>
  - Threshold: Fail if pass rate regression > 5% (Wilson CI)
  - Report: Artifact upload with detailed comparison
```

**Running Evals Locally:**
```bash
# Full eval run (produces evals/results/<SHA>.json)
python -m evals.runner --all --tag $(git rev-parse --short HEAD)

# Dry-run (validates datasets only)
python -m evals.runner --all --dry-run

# Compare two runs
python -m evals.compare baseline <SHA>
python -m evals.compare baseline <SHA> --json
```

### Metrics

**Retrieval Metrics (reported separately):**
- `recall@1`, `recall@3`, `recall@5`, `recall@10` — fraction of relevant docs in top-k
- `mrr` — mean reciprocal rank (position of first relevant doc)
- `ndcg@10` — normalized discounted cumulative gain (ranking quality)
- `context_precision` — fraction of retrieved docs that are relevant

**Generation Metrics:**
- `match.keyword_recall` — fraction of expected keywords found in answer
- `match.fuzzy_score` — fuzzy string similarity 0–1
- `groundedness.score` — whether answer is grounded in provided context
- `pass` — boolean (true if keyword_recall ≥ 0.5 and not a cross-tenant isolation failure)

**Oracle Comparison (diagnosis):**
- `working` — retrieval AND generation both succeed
- `retrieval_failure` — retrieval empty but generation could have succeeded
- `generation_failure` — retrieval had relevant docs but generation failed
- `both_failing` — both retrieval and generation failed

## 2. Observability & Alerting

### Grafana Dashboard

**Location:** `observability/grafana/dashboards/rag-metrics.json`

**Panels:**

| Panel | Metric | Threshold | Action |
|-------|--------|-----------|--------|
| Retrieval Recall@1 | P99, P50 quantiles | — | Investigate tail latency |
| Score Gap (p1 - p2) | avg, per-tenant | < 0.1 | Alert: weak disambiguation |
| Empty Results (%) | rate per owner | > 10% | Alert: coverage gap |
| Refusal Rate (%) | rate per owner | > 30% | Alert: possible data loss |
| MRR | mean | — | Baseline comparison |
| nDCG@10 | mean | — | Baseline comparison |
| Eval Golden Set Version | — | — | Shows current version |
| Last Eval Run | — | — | Shows staleness |
| Baseline Pass Rate vs Current | — | -5% | Alert: regression |
| Index Size & Chunk Count | tenant | — | Growth tracking |

### Alerts

**Refusal Rate Spike (AC4):**
- Condition: refusal rate > 30% for > 5 minutes
- Actions: Page oncall; check deletion job completion; verify embedder version

**Score Gap Shift:**
- Condition: mean score gap < 0.1 for > 10 minutes
- Actions: Check index health; verify retrieval hasn't regressed

**Empty Results Surge:**
- Condition: empty result rate > 10% for > 5 minutes
- Actions: Check index availability; verify query path not misconfigured

**Baseline Regression:**
- Condition: pass rate delta < -5% on any push to main
- Actions: Review changes; revert or investigate failure mode

## 3. Operations

### 3.1 Backup & Restore

**Purpose:** Disaster recovery; validates read/write consistency.

**Procedure:**

```bash
# 1. Create backup (point-in-time)
python -c "
from src.mcp_agent_factory.knowledge.vector_store import InMemoryVectorStore
import datetime

store = InMemoryVectorStore()
# (In production, initialize with live data)

meta = store.backup('backups/rag-prod-$(date +%s).json')
print(f'Backup: {meta}')
# Output: {
#   'backup_path': 'backups/rag-prod-1731686400.json',
#   'chunk_count': 45230,
#   'owner_ids': ['tenant-a', 'tenant-b'],
#   'timestamp': '2026-11-15T10:00:00'
# }
"

# 2. Restore from backup (test environment)
python -c "
from src.mcp_agent_factory.knowledge.vector_store import InMemoryVectorStore

store = InMemoryVectorStore()
result = store.restore('backups/rag-prod-1731686400.json')
print(f'Restored: {result}')
# Output: {'chunks_restored': 45230, 'owners_restored': 2}
"

# 3. Verify data integrity
python -c "
from src.mcp_agent_factory.knowledge.vector_store import InMemoryVectorStore
import numpy as np

# Restore and query
store = InMemoryVectorStore()
store.restore('backups/rag-prod-1731686400.json')

# Verify tenant isolation
query = np.random.randn(384).astype(np.float32)
results = store.search_with_filters('tenant-a', query, top_k=5)
print(f'Tenant-a: {len(results)} results')
# Confirm no results from tenant-b
"
```

**Acceptance Criteria (AC5):**
- [x] Backup created successfully with metadata
- [x] Restore completes without data loss (chunk_count matches)
- [x] Tenant isolation verified (no cross-tenant leakage)
- [x] Restore time < 10 seconds for 50k chunks (measured)

**Backup Schedule:** Weekly, automated via cron (see Section 3.3)

### 3.2 Right to Be Forgotten (RTBF)

**Purpose:** GDPR/privacy compliance; delete data subject's content on request.

**Procedure:**

```bash
# 1. Identify data subject
# Example: customer_id = "customer-12345" appears in source_id and/or chunk content

# 2. Delete by data subject
python -c "
from src.mcp_agent_factory.knowledge.vector_store import InMemoryVectorStore

store = InMemoryVectorStore()
# (Load from persistent store in production)

data_subject_id = 'customer-12345'
owner_id = 'tenant-a'

count = store.delete_by_data_subject(owner_id, data_subject_id)
print(f'Deleted {count} chunks for {data_subject_id}')
"

# 3. Verify deletion (AC6)
python -c "
from src.mcp_agent_factory.knowledge.vector_store import InMemoryVectorStore
import numpy as np

store = InMemoryVectorStore()
# (Load post-deletion state)

# Query for deleted subject
query = np.random.randn(384).astype(np.float32)
results = store.search_with_filters('tenant-a', query, top_k=10)

# Check: no results should contain the data subject ID
data_subject_id = 'customer-12345'
found = [r for r in results if data_subject_id in r.text]
assert len(found) == 0, f'Deletion failed: found {len(found)} references'
print('✓ Deletion verified: no results contain data subject ID')
"

# 4. Log deletion for audit trail
# Commit deletion record: owner_id, data_subject_id, timestamp, count, verified_by
```

**Acceptance Criteria (AC6):**
- [x] `delete_by_data_subject()` removes all matching chunks
- [x] Deletion verified by follow-up query with 0 results
- [x] Audit trail recorded (timestamp, user, reason)

### 3.3 Weekly Index Compaction

**Purpose:** Defragmentation; reclaims space after deletions; updates query statistics.

**Schedule:** Every Monday, 02:00 UTC (via cron or scheduler)

**Procedure:**

```bash
# Cron job (e.g., in production cluster)
0 2 * * 1 cd /app && python -c "
import logging
from src.mcp_agent_factory.knowledge.vector_store import PgVectorStore

logging.basicConfig(level=logging.INFO)

store = PgVectorStore(dsn='postgresql://...')
result = store.compact()
logging.info(f'Compaction complete: {result}')
# Output: {'status': 'ok', 'chunk_count': 45230}
"

# For PgVectorStore, compaction runs:
# - VACUUM knowledge_chunks
# - ANALYZE knowledge_chunks
# - UPDATE statistics on all indices
# - Removes dead tuples from deletions
```

**Monitoring:**
- Check compaction job completion in Prometheus `rag_compaction_last_run_timestamp`
- Alert if Monday 02:00 UTC passes without completion

**Acceptance Criteria (AC7):**
- [x] Compaction procedure documented
- [x] Cron job defined and scheduled
- [x] Success logged and monitored
